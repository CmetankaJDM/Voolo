# Rich Messages в Voolo

Как бот говорит с пользователем. Код лежит в `apps/bot/src/rich/`.

Rich Messages появились в Bot API 10.1 (11 июня 2026) и расширились в 10.2
(14 июля 2026). Это первый раз, когда бот может отправить в чат настоящую
таблицу и сворачиваемый блок, а не имитацию из пробелов.

Для агрегатора авиабилетов это попадание в цель: выдача — это таблица
«дата / цена / пересадки / авиакомпания», и до 10.1 её приходилось рисовать
моноширинным шрифтом и молиться, чтобы не поехала вёрстка на узком экране.

## Формат запроса

```jsonc
// POST https://api.telegram.org/bot<token>/sendRichMessage
{
  "chat_id": 123456,
  "rich_message": {
    // Ровно ОДНО из трёх: blocks | html | markdown
    "blocks": [
      { "type": "heading", "size": 3, "text": "MOW → HKT" },
      { "type": "paragraph", "text": "Лучшая цена в кэше" }
    ]
  }
}
```

Лимит сообщения — **32 768 UTF-8 символов**, включая alt-текст custom emoji
и исходник формул. Константа живёт в `RICH_MESSAGE_MAX_LENGTH`.

Главное отличие от старого API: больше нет `MessageEntity[]` с UTF-16
оффсетами. Форматирование вложено в сам текст (`RichText`), и целый класс
ошибок «эмодзи сломало разметку» исчезает.

## Блоки, которые мы реально используем

| Блок | Где в Voolo | Почему именно он |
| --- | --- | --- |
| `table` | выдача билетов, календарь цен | данные табличны по природе |
| `details` | «Как мы считаем», длинные списки | честность без портянки |
| `footer` | дисклеймер о свежести цены | мелкий текст не кричит, но виден |
| `marked` | лучшая цена в строке | подсветка вместо третьего эмодзи |
| `thinking` | прогресс поиска | с `sendRichMessageDraft` даёт живой статус |
| `list` | подсказки, преимущества Plus | есть чекбоксы без костылей |
| `divider` | раздел выдачи и пейволла | дешёвый способ разбить экран |

Не используем в MVP: `collage`, `slideshow`, `audio`, `video`, `pullquote`,
`anchor`. Они описаны в типах, но ни один шаблон их не вызывает.

## Таблица: что важно знать

- `cells` — это массив строк, каждая строка — массив ячеек.
- `align` и `valign` НЕ опциональны. Хелперы `td` и `th` подставляют
  `"left"` и `"middle"`, чтобы об этом не думать.
- Ячейка без `text` — невидимая. Нужна там, где соседняя растянута
  через `colspan` или `rowspan`. Хелпер — `tdEmpty()`.
- У таблицы `caption` — это `RichText`. У медиа-блоков — `RichBlockCaption`
  с полями `text` и `credit`. Легко перепутать.
- Ширина экрана конечна. Четыре колонки — потолок для телефона.

## Списки: неочевидное

У `InputRichBlockListItem` **нет** поля `label` и у `list` **нет** `is_ordered`.
То и другое есть только в полученных сообщениях. Нумерацию рисует клиент.
Если нужен гарантированный порядок с конкретными номерами — пишите цифры
в текст сами.

## Фолбэк — не опция

`RichClient.sendBlocks()` сначала пробует `sendRichMessage`. Если метода нет
(`method not found`), клиент запоминает это в памяти изолята и больше не
тратит на него запросы. Дальше те же блоки уплощаются в HTML и уходят
обычным `sendMessage`.

Как выглядит деградация:

| Блок | В HTML-фолбэке |
| --- | --- |
| `heading` | `<b>` |
| `footer` | `<i>` |
| `divider` | строка из десяти `─` |
| `table` | моноширинная сетка в `<pre>` с выравниванием колонок |
| `list` | `•` / `☐` / `☑️` |
| `details` | `<b>summary</b>` плюс `<blockquote expandable>` |
| `marked` | `<i>` — подсветки в HTML просто нет |
| `anchor` | выбрасывается |
| медиа-блоки | выбрасываются осознанно |

Медиа выбрасывается не по лени: картинку нельзя вложить в текстовое
сообщение, её надо шлать отдельным методом. Молчаливо превратить
фото в ссылку было бы хуже, чем её не показать.

## Статус проверки типов

В `types.ts` каждый блок помечен `VERIFIED` или `UNVERIFIED`.

- **VERIFIED** — сверено с core.telegram.org/bots/api. Сюда попадают все блоки,
  которые реально используют шаблоны Voolo.
- **UNVERIFIED** — имя поля выведено по аналогии: `photo`, `map`,
  `mathematical_expression` как блок, поля `custom_emoji`,
  `InputRichMessageMedia`. Ни один из них не на критическом пути.

Проверить живым запросом: `pnpm tsx scripts/verify-rich-blocks.ts`.
Скрипт шлёт каждый тип блока в указанный чат и печатает таблицу
«прошёл / не прошёл».

## Почему не через grammY

grammY на момент написания не типизирует `sendRichMessage` — методам
меньше двух месяцев. Поэтому `rich/` ходит в Bot API напрямую через
`fetch`. Всё остальное — апдейты, сессии, клавиатуры, платежи — через grammY.

Когда grammY добавит поддержку, миграция — это замена тела `call()`
в `client.ts`. Шаблоны и билдеры не меняются.

## Правила тона

1. **Не более двух эмодзи на сообщение.** Обычно одно — в заголовке.
   Акцент внутри текста делается `marked`, а не ещё одной картинкой.
2. **Цена из кэша всегда с датой находки.** `freshnessNote()` обязателен
   в каждом шаблоне с ценой. Это не юридическая формальность, а главный
   способ не потерять доверие после первого же расхождения цены.
3. **Вся вёрстка живёт в `templates.ts`.** В хендлерах не должно быть
   ни одной склеенной строки с разметкой.
